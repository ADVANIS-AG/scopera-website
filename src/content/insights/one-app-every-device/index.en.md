The old trade-off went like this: either a web application that runs everywhere and does little. Or native apps for iOS, Android and desktop that do a lot and cost a lot. Three codebases, three release cycles, three times the maintenance.

## What is possible today

- **One application, every device**: The same interface adapts from desktop to phone. It gets built once.
- **Access to the camera**: Take photos right in the record, or measure distances and areas on a photo, without installing anything.
- **No rollout in the browser**: No installation, no versions on devices, no waiting for app store approval.

## Where the limit is

Some use cases still call for a native app. The LiDAR room scan is one of them: it runs in the SCOPERA app for iPhone and iPad, which we provide by invitation. Graphics-heavy work is another, and the web application does not use the device location today. For most business applications inside a company, the browser is enough. We push what works without separate native development, and we say so openly when a requirement goes beyond it.

## Where to start?

Check which of your mobile workflows really need device functions. Usually it is the camera, and that is covered. For anything further, we work out the right path with you.
